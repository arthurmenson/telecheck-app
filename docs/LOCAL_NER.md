# Local statistical PII screening

`npm ci && npm run ner:setup && npm run build && npm run ner:verify` installs and verifies the pinned model. Setup has build-time network access; serving performs local CPU inference only. Model bytes are not committed. The model manifest pins revision, file sizes, SHA-256 digests and labels. The container packages assets read-only alongside publisher/license attribution, uses Debian/glibc, and is tested by running the actual inference probe with `--network none --read-only`.

The OpenMed ClinicalE5 Small 33M INT8 classifier supplies English name, organization, birth-date and location/address predictions. The implementation selects first/last names (high policy confidence), date of birth (high), city/country/county/state, street/postcode/coordinate and company (low). Other model classes are not claimed here; existing regex controls remain independent. Winning probabilities are not treated as policy confidence or discarded with a probability threshold. This is a risk-reduction layer; a pass does not certify arbitrary text PII-free or authorize a provider to process clinical information.

Full untruncated source encoding is sliced into 382-token bodies with 64-token overlap, plus inserted CLS/SEP tokens. This deliberately avoids the pinned native tokenizer's observed incomplete overflow coverage. Source token coverage and code-point offsets are validated and mapped to UTF-16. Full word pieces and attached surname components (apostrophes/hyphens, at most 256 characters) are included after a real PERSON prediction. Interval union prevents overlapping hits from leaking a suffix. Literal source special tokens and unknown tokens retain their source coverage.

Limits are 16,000 UTF-16 units, 4,096 source tokens, 13 windows, two in-flight requests per process, no wait queue and a ten-second response deadline. A timed-out native job retains capacity until settlement; this is not native cancellation. Chat applies its existing 4,000-character limit after crisis detection and before inference. Admin decisions allow 64 collected strings, 16,000 total characters, 256 traversed nodes and the existing depth limit. Oversized, malformed or incomplete work fails closed.

`screenInput`/`screenOutput` are async. Any asset, native, shape, nonfinite-output, offset or capacity error blocks ingress with static safe diagnostics. Unverified egress is replaced in full with `[REDACTED:Unverified output]`; the same replacement is displayed and persisted. Candidate text, hits and native error messages are not logged. Low-only internal hits redact; high hits block. AI/audit routes block any accepted hit.

Startup warms the model without preventing the HTTP listener or crisis branch from operating. `/ready/pii` returns 503 until verified/warmed/healthy capacity is available. `/health` stays live; do not configure the whole service's load balancer against PII readiness and thereby drain crisis access. Inference stalls require operational process replacement after preserving crisis capacity elsewhere. There is no runtime model acquisition or automatic unpinned update.

Tests include real US/Ghana English synthetic names and streets, lowercase and decomposed text, repeated names, source special tokens, complete token windows, overlap union, negative medical/reviewer language, budgets, deadline capacity, missing/corrupt assets, invalid outputs, provider suppression, persisted/displayed output equality and crisis ordering. These finite regressions are not representative geographic recall estimates. Twi, Ga, Ewe and code-switched coverage are not validated. A separate held-out clinical evaluation, operational load evidence, approved processing posture and independent review remain required before real-data release. Backend NER cannot inspect client-sealed ciphertext; plaintext-ingress/client screening coverage must be implemented independently.
